V3 相对 V2，变了三件事

V2 讨论的是「本地生成 + 云端上线」的产品形态，那部分结论继续有效。V3 换的是实现路径。

变 化 一 　 地 基
不再新起工程，落在 MicaBase 上

V2 写的是「复用你们已有的 Rust 客户端底座」，当时没具体到哪个。现在明确了： youxi/ 就是 MicaBase，六模块分层已经成型、边界有脚本强制、 SSE 流式与任务生命周期都跑通了，apps/desktop 正好是留白的 Tauri 壳。

变 化 二 　 移 植
三块能力整体搬过来，不重写

polaris-app 里的环境医生、cc-switch 供应商切换、技能库， 加起来后端约 450 KB、前端约 180 KB 的实战代码。 这些不是"参考实现"，是已经处理过安装冲突、代理串台、PATH 污染的东西。重写等于把坑重踩一遍。

变 化 三 　 引 擎
去掉强制分流，生图交给 MiniMax

MicaBase 现在强制「长文本永不落 codex」。V3 按你的决定取消这套强制路由： 文本走 Claude Code CLI，生图直接调 MiniMax API（少一个必装依赖）， codex CLI 保留为可选后端引擎，需要时能顶上。

两个已经踩过的坑，写进 V3 免得再踩

① wrangler r2 object put 默认写本地。wrangler 4.90 默认 --local， 写进 .wrangler\state\v3\r2\。最阴的是 get 也读本地——put 成功、get 读回来内容正确， 但线上绑定看到的是空桶。所有 R2 命令必须带 --remote。 做「生成完自动上传」时一定会再遇到。

还没验的那一项，是最关键的

大厅：六条硬规则已落到代码里

不是写在文档里靠自觉，是写死在 hall.js 的 CSS 与模板里：

  • ① 封面统一 16:10 居中裁切 —— aspect-ratio:16/10 + object-fit:cover，作品站再花哨，在大厅里也只是一张标准卡；
  • ② 信息固定三行 —— 标题单行省略（不换行、不缩字号）/ 头像+姓名 / 点击数；
  • ③ 只有两种尺寸 —— Top3 大卡（16:9）+ 其余同尺寸小卡，没有参差瀑布流；
  • ④ 卡片样式不被内容影响 —— 大厅有自己的设计语言，不继承作品的；
  • ⑤ 先审后展 —— status != 'public' 的作品不出现在任何列表；
  • ⑥ 永不空榜 —— 没有数据时出引导态而不是空白，并预埋样例作品打底。

排序 点击数 / (小时数+2)^1.2，最热 / 最新双 Tab。没有真实封面时用确定性生成的版式示意图 （导航条 / 标题块 / 正文行 / 卡片栅格），看上去就是"一个网页"，而不是一坨占位灰块。

内容安全：下架必须是真的下架

这块在联调中被抓出三个 bug，都已修复并实测确认。写在这里是因为第一个是现场硬伤：

问题原来的表现修复
下架只是从列表消失 status=hidden 之后，作品站 /u/<slug>/ 仍返回 200、 海报页与海报 SVG 也仍返回 200。真出内容事故时等于没有开关。 页面导航在读缓存之前先查在架状态（放缓存之后判会被已缓存的页面绕过）； 海报与详情接口同样加判。运维通道带令牌仍可查看，方便复核。
status 没有白名单 {"status":"banana"} 返回 ok，作品变成既非 public 也非 hidden 的幽灵态。 限定 public|hidden；cover/poster 也限定前缀与字符集。
幽灵点击 对不存在的作品记点击返回 counted:true，并在 hits 表留下孤儿行。 先确认作品存在且在架再记数。

实测：下架后站点 / 海报 / 海报 SVG / 公开详情接口四项全部 404，运维接口仍 200；恢复后全部回到 200。

运维上必须记住的一条

Worker 版本在各个 PoP 之间不是瞬时同步的。实测部署后几秒内， 同一个 URL 打到 TPE 机房拿到新版本、打到 SJC 还是旧版本，表现为"同样的请求一会儿成功一会儿 404"。 活动当天绝对不要在演示前几十秒部署；改完至少留 2 分钟再验。

分享海报：补上的最后一环

作品做完之后，用户要有一张能直接发出去的东西。这张海报是自动生成的， 不需要任何人做图，五个要素齐全。

① ② 　 人 与 作 品
创作者姓名 + 主题 + 一句话亮点

姓名放在顶部显著位，字号按长度自适应（24 字上限时固定字号会冲出画布，实测踩过）。 标题最多 2 行、亮点最多 2 行，超出省略号收尾。

③ 　 画 面
作品画面示意

优先用桌面端回传的真实首屏截图；没有截图时用由作品 id 派生的确定性版式图， 同一作品每次都长一样，不会今天蓝明天紫。

④ ⑤ 　 入 口 与 品 牌
体验二维码 + 活动主题元素

二维码直接指向作品地址；活动元素为「现场共创」徽章、活动名、日期、口号与 深空底＋光线＋网格的统一视觉。

二维码是自己实现的，而且验到能扫为止

Worker 里装不了 npm 包，所以 QR 编码器（byte 模式 · RS 纠错 · 8 种掩码择优 · V1–V15）是零依赖手写的。 「看起来像二维码」不算数，所以做了两层验证：
· 编码器层：用 jsQR 真解码回来逐字比对，7 个定向用例 + 120 个随机 fuzz，127/127 通过，覆盖 V1–V11（含 V7+ 的版本信息块）。
· 渲染层：把海报 SVG 真的栅格化成 1080×1440 PNG，再从像素里解码，4/4 通过—— 因为海报里是手工把模块画成 <path>，单元格是浮点尺寸，取整误差完全可能把它毁掉。

开发过程中真踩到的一个坑，值得记下来

第一版二维码结构全对——定位图形、定时图形、校正图形、固定暗模块，逐项自检全过， 肉眼看也完全像个正常二维码——但扫描器一个都读不出来。 原因是格式信息的位序写反了：标准要求 MSB 先放，我按 LSB 先放。
这类 bug 靠"看"永远发现不了，只能靠真解码。凡是要被机器读的东西，验收标准必须是"机器能读"，不是"人看着对"。
